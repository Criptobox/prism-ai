6 herramientas que faltan al agente

Hoy el agente sabe hacer 6 cosas: get_quota · list_files · read_file · read_url · run_project · write_file. El salto más grande de la app está aquí: pasar de «agente que escribe archivos» a «operador que prueba, corrige y decide» — con las mismas garantías locales de siempre (permisos, proxy anti-SSRF, registro visible).

edit_file
edición quirúrgica · riesgo: escritura

Cambia solo los bloques que el modelo marca, con búsqueda/reemplazo exacto. Hoy write_file reescribe el archivo entero: un cambio de 3 líneas en un archivo de 400 cuesta 400 líneas de tokens y puede regalar el resto. edit_file gasta 6× menos y no toca lo que no debe.

// tool call — solo el bloque a cambiar "find": "<section class=\"hero\">" "replace": "<section class=\"hero\" data-lp>" // resultado en styles.css

run_js
REPL instantáneo · riesgo: sandbox

Ejecuta un snippet de JS en el mismo marco aislado del Sandbox y devuelve el resultado en el acto. run_project arranca el proyecto entero; run_js responde «¿y si cambio esta función?» en 200 ms. El agente puede probar su lógica antes de escribir el archivo — bucles de error de 30 segundos pasan a ser de 1.

// el agente prueba antes de tocar el archivo const precios = [4.5, 6, 9]; precios.map(p => p.toLocaleString("es", { style: "currency", currency: "EUR" })) → out [ "4,50 €", "6,00 €", "9,00 €" ] ✓ 0 errores · 180 ms · sin red

search_web
búsqueda real · riesgo: red (proxy)

El agente hoy solo puede leer una URL exacta (read_url) que le des. Con search_web puede encontrar: la API correcta, la sintaxis de 2026, el changelog. Motor: HTML de Bing/DuckDuckGo vía tu proxy anti-SSRF + los 3 primeros resultados re-leídos con read_url. Sin claves, sin registrarse.

read_console
el agente ve sus errores · riesgo: lectura

La regresión ya mide la consola después de ejecutar. El hueco: en medio del bucle, el agente no puede preguntar «¿qué error hay ahora mismo?». read_console le devuelve los últimos mensajes de consola del Sandbox y así se autocorrige en la misma iteración, en vez de terminar la respuesta con el bug dentro.

fetch_api
JSON estructurado · riesgo: red (proxy)

read_url devuelve texto plano: si el agente necesita una API (el tiempo, tipos de cambio, datos abiertos), hoy debe parsear HTML a lo ciego. fetch_api pide JSON por el proxy, valida el esquema y devuelve solo los campos pedidos — menos tokens, cero alucinación sobre la respuesta.

"url": "api.open-meteo.com/v1/forecast" "fields": ["temperature_2m", "wind_speed_10m"] → out (2 campos, no 40) { "temperature_2m": 28.4, "wind_speed_10m": 11.2 } ✓ schema ok · 61 tokens en vez de 1.8k

git_snapshot
puntos de restauración · riesgo: escritura

El agente trabaja en el Sandbox y las regeneraciones ramifican los mensajes, pero el proyecto no tiene historia propia. git_snapshot crea un punto de restauración (copia local comprimida + mensaje) antes de cambios grandes: «después de esa optimización que rompió todo, volver atrás es 1 clic — o 1 tool call para el propio agente.

→ snapshots del sandbox (local, comprimido) s3 ● iter 3 · precios + glass (actual) s2 ● hero + nav responsivos s1 ● esqueleto de plantilla → rollback a s2 en 0.8s · 214 kB

6 utilidades que cambian el día a día

Todas respetan la filosofía del proyecto: sin servidores propios, sin cuentas nuevas, todo local o por servicios que ya conectaste. Las dos primeras (Sync y Snippets) son las que más pide la gente cuando usa la app en dos dispositivos.

Prism Sync

Tus chats, claves cifradas y ajustes sincronizados entre móvil y PC sin montar servidor: un gist privado de tu GitHub (ya conectado en la app) como bandeja de sincronización, cifrado AES-GCM con tu PIN de la bóveda. Merge por marcas de tiempo, conflicto resuelto a mano.

Cola offline

El service worker ya da offline estático, pero si escribes sin red el mensaje se pierde o da error. Con cola: se guarda, se muestra como «pendiente» con los previos desactivados, y al volver la conexión se envía en orden y avisa por notificación. Pensado para el uso real en móvil.
